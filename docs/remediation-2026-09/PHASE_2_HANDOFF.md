## 1. The MCP connection — fixed, and it was not the token

**Your PAT is fine. Do not regenerate it.** It returns HTTP 200 against
`https://api.supabase.com/v1/projects` and it authenticated every read in this
session.

The failure was `.mcp.json`'s `${SUPABASE_PAT}` **not being expanded** — the
literal seven-character string `${SUPABASE_PAT}` went over the wire as the bearer
token. Reproduced against the live endpoint:

| What is sent | Response |
|---|---|
| the real PAT | `HTTP 200` |
| an **empty** bearer | `HTTP 401` · `Format is Authorization: Bearer [token]` |
| the literal `${SUPABASE_PAT}` | `HTTP 401` · **`JWT could not be decoded`** |

The third is the error you saw, exactly. An unset variable would have produced
the *second* message, so this is not "the variable is empty" — the placeholder
was transmitted verbatim, which happens when the launching process has no
`SUPABASE_PAT` in its environment at all.

`SUPABASE_PAT` is exported in `~/.zshrc`. A VS Code (or Claude Code) launched
from the Dock or Finder does not source `~/.zshrc`, so it never sees it. Launched
from a terminal, it does. That is the whole bug, and it explains why it works now
and failed before.

**It is working in this session** — every figure in the reconciliation came
through it. To stop it recurring, see NEEDS TANNER step 1.

## One thing to know about how I checked

Content comparison between a repo file and its history row uses token
containment, not `difflib.SequenceMatcher.ratio()`. `SequenceMatcher` has an
autojunk heuristic that ignores any character appearing in more than 1% of a
sequence longer than 200 elements, which makes character-level ratios on SQL
meaningless — it initially scored two files that differ **only** by `begin;` and
`commit;` at 0.13 similarity. If you re-run any of this, do not trust a
`SequenceMatcher` ratio on long strings without `autojunk=False`.
